# Lab 1 Submission Instructions

Submit your Lab 1 work through the **Lab 1 submission activity in Moodle**.

In Moodle, submit the **URL of your forked GitHub repository** containing your completed Lab 1 work.

In the Moodle submission text, include:

1. **Repository URL**
   - Provide a link to your fork of the course repository.
   - Make sure the repository is accessible to the instructor.

2. **Work completed**
   - Briefly describe what you completed during the lab.
   - Organize your description by the relevant source-code files in `src/`.
   - For each file, state what you implemented, changed, tested, or investigated.

   Example:
   - `src/example1.cpp` — implemented ..., tested ..., observed ...
   - `src/example2.cpp` — modified ..., compared ..., verified ...
   - `src/example3.cpp` — investigated ...

3. **Blockers and challenges**
   - Mention any technical or conceptual problems you encountered.
   - Explain briefly how you solved them, or state that they remain unresolved.
   - If you had no significant blockers, simply write **No major blockers**.

4. **Incomplete work**
   - Clearly identify anything you did not complete or could not get working.

Keep the submission concise. A short list is sufficient. The purpose is to document **what you actually worked on and what you learned**, not to write a formal report.

**Important:** Your completed source code should be committed and pushed to your forked repository before you submit its URL in Moodle. GitHub is where your code is stored; **Moodle is the official submission location for the lab**.
