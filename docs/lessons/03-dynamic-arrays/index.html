Arrays and Dynamic Arrays

1. Why dynamic arrays exist

Contiguity gives direct indexed access. Spare capacity buys cheap future appends. The trade-off is unused memory and occasional expensive relocation. Week 2 covered ownership and lifetime; Week 4 will compare linked structures.

2. Anatomy and addressing

For an element type T, address(i) = base + i × sizeof(T). Logical range [0,size); spare slots are not logical elements. Buffer bytes = capacity × sizeof(T), excluding object metadata and allocator overhead.

IntVector invariant: 0 ≤ size ≤ capacity; capacity is zero iff data is nullptr. Positive capacity requires a live allocation of at least that many int slots.

3. Construct and operate

Load a preset, enter a comma-separated sequence (empty is allowed), or generate six seeded values. Capacity is capped at 128. Operations follow a teaching doubling policy, not a mandated std::vector growth factor.

4. Operation microscope

Trace an independent copy; importing again is explicit. Predict allocation, transfers and shifts before playback. Transient slots show the intermediate work; stable logical size changes only when the operation completes.

5. Growth strategy experiment

Compare fixed increments and geometric growth. Each transfer counts one existing element. Total modeled work = transfers + append writes; peak slots include both buffers during reallocation.

6. Amortized analysis

Growth by one transfers 0+1+…+(n−1)=n(n−1)/2=Θ(n²). Fixed increments also give quadratic total work. Doubling transfers 1+2+4+… < 2n; including n append writes gives Θ(n) total, or Θ(1) amortized per append. A single growing append is Θ(n); no probability distribution is assumed.

Extra buffer during growth is Θ(n) for geometric policies. A reserve request may allocate substantially more than size.

7. Pointer and iterator validity

Choose a handle and operation for a modeled vector of four elements. A past-the-end iterator is not an element pointer. Reallocation ends old storage lifetime; a saved pointer does not follow the new buffer.

Without growth, insertion/erase invalidates handles at or after the position; append invalidates old end but not existing elements; clear invalidates element handles. Never dereference an invalid pointer.

8. Copying, moving and ownership

RAII ties release to the owning object's lifetime. A shallow copy of a raw owning pointer violates unique ownership; a deep copy has independent storage. Moving can transfer the resource; the empty moved-from state below is a teaching convention, not a general guarantee. Week 3 requires copy construction, not the full Rule of Five.

9. Invariant debugger

Repair metadata or choose the correct repair action. Keep logical values, allocation sizes and ownership consistent. These are independent scenarios, not assessed lab code.

10. Spatial locality

Equal numbers of element accesses can touch different numbers of simulated cache lines. This is an aligned-memory model, not a CPU timing or cache-miss simulation.

11. Engineering decisions

Dynamic arrays favor indexed access, sequential traversal and frequent appends. Front insertion shifts all elements; strict worst-case append latency and stable addresses during growth may require another representation. Reserve can avoid growth until its capacity is exhausted. Use std::vector in production unless a different representation is justified.

12. C++20 reference (optional)

Independent examples illustrate concepts; no complete IntVector implementation. Compile locally or in Codespaces.

contiguous-addressing.cpp

Observe actual element spacing.

#include <array>
#include <iostream>
int main(){std::array<int,4> a{10,20,30,40}; for(auto& x:a) std::cout << static_cast<const void*>(&x) << '\n'; std::cout << sizeof(int) << '\n';}

Output: Four consecutive addresses spaced by sizeof(int); addresses vary.
